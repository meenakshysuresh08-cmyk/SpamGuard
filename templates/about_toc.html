1. Introduction to Formal Language Theory

Foundations of abstract machines and formal computational models

Mathematical Foundation

In the Theory of Computation (TOC), computation is analyzed through formal mathematical models rather than specific hardware or empirical heuristics. A fundamental question is: what can an abstract automaton recognize when memory is strictly bounded?

Email spam detection is traditionally approached using heavy, opaque Machine Learning (ML) models like Naive Bayes, Support Vector Machines, or Large Language Models (LLMs). While flexible, ML models suffer from non-determinism, high computational latency, adversarial evasion (such as prompt injections or invisible characters), and zero formal behavioral guarantees.

SpamGuard demonstrates that core TOC primitives—Regular Expressions (RE) and Deterministic Finite Automata (DFA)—can classify email sequences deterministically in linear time $O(n)$ with constant space $O(1)$.

2. The Chomsky Language Hierarchy

Where SpamGuard's recognition engine lives in formal grammar classification

Classification Hierarchy
Type-3: Regular Languages (SpamGuard Engine) Recognized by: Finite State Automata (DFA / NFA)

Memory: No auxiliary memory. State tracks finite history. Power: Regular Expressions.

Type-2: Context-Free Languages Recognized by: Pushdown Automata (PDA)

Memory: Single LIFO stack. Capable of parsing nested structures (e.g. HTML/JSON brackets).

Type-1: Context-Sensitive Languages Recognized by: Linear-Bounded Automata (LBA)

Memory: Tape bounded by input length. Context determines replacement rules.

Type-0: Recursively Enumerable Recognized by: Turing Machines (TM)

Memory: Infinite read/write tape. Equivalent to general-purpose computing.

3. Kleene's Equivalence Theorem

Mathematical equivalence of Regular Expressions and Finite Automata

RE ≡ DFA ≡ NFA

A cornerstone theorem of Automata Theory proven by Stephen Cole Kleene states:

Kleene's Theorem
"A language L over an alphabet Σ is recognized by a Deterministic Finite Automaton (DFA) if and only if L can be described by a Regular Expression (RE)."

In SpamGuard, this equivalence is used in two complementary stages:

  1. Micro-Recognition (Regular Expressions): Scans the raw character stream $\Sigma_{\text{text}}^*$ to detect individual phishing heuristics (domain syntax, lure wording, credential keywords).
  2. Macro-Validation (Deterministic Finite Automaton): Evaluates whether the sequence of detected tokens forms an accepted social-engineering attack trajectory in the token language $\Sigma_{\text{token}}^*$.

4. Formal Mathematical Specification of SpamGuard's DFA

Exact formal 5-tuple M = (Q, Σ, δ, q₀, F)

Formal Automaton
Q
Finite Set of States: { q0, q1, q2, q3, q4, q_dead }

Where q0 = Initial state, q1 = Lure Detected, q2 = Pressure Applied, q3 = Suspicious Link Reached, q4 = Credential Theft Attempted, q_dead = Sink state.

Σ
Input Alphabet: { LURE, URGENT, URL, CREDENTIAL, OTHER }

Discrete token symbols extracted from incoming email content.

q₀
Start / Initial State: q0 ∈ Q

The automaton always starts in state q0 before reading the first token.

F
Set of Accepting / Final States: { q3, q4 } ⊆ Q

If the input sequence drives the automaton to either q3 (malicious link) or q4 (credential request), the sequence is mathematically accepted as spam pattern.

δ
Transition Function: δ: Q × Σ → Q

A total function mapping every (state, symbol) pair to exactly one next state, guaranteeing determinism.
